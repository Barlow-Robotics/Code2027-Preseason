Try it

Open the simulator and graph

  1. Save all files. If a simulator is already running, stop it before starting the new code.
  2. In VS Code, press Ctrl+Shift+P. Choose WPILib: Simulate Robot Code, then Sim GUI if prompted.
  3. Connect the Xbox controller. In System Joysticks, drag it onto Joystick[1]. This is the operator controller. Leave the robot disabled while arranging the windows.
  4. Open AdvantageScope (WPILib). Choose File → Connect to Simulator, selecting NetworkTables if prompted.
  5. Add a Line Graph tab. Expand Telemetry → Elevator and drag Target_m and Actual_m into the graph. Add MovementActive to see when the command is running; add Velocity_mps to see its motion.
  6. In the Sim GUI, select Teleoperated and Enabled.

If you need help locating these controls, see the first walkthrough’s simulator instructions.

Plot selection and movement

First, try each destination after the previous trip has finished. Then we will test what happens when we press the same button twice during travel.

Add SelectedHeight_m to the height graph. To read the selected name, add a Table tab and drag SelectedLevel into it.

  1. Tap Y once. SelectedLevel becomes MID, and Actual_m rises toward 0.35 m. MovementActive stays true after you release the button.
  2. Wait for arrival. MovementActive becomes false, and the elevator holds near MID. Target_m may differ slightly from SelectedHeight_m because cleanup holds the measured position.
  3. Tap Y again to go to TOP. Tap Y at TOP: the selected level stays TOP. Hold Y to confirm it does not repeatedly advance.
  4. Tap A to select MID. Wait for arrival, then tap A again to select BOTTOM.
  5. At BOTTOM, tap A again. Selection stays BOTTOM.

Interrupt a trip

Tap Y to begin traveling, then disable the simulator before arrival. MovementActive becomes false. Disabling also removes motor power, so gravity may lower the elevator while disabled. Enable again without pressing a button: it must not resume the old trip. It may settle toward the position captured by cleanup; this is holding behavior, not a renewed trip to the selected level.

SelectedLevel still remembers the interrupted destination. The next increase or decrease operates on that selection. For example, if TOP was selected before interruption, A requests MID regardless of the current measured height.

Try two quick presses

Return to BOTTOM and wait for arrival. Tap Y, wait about one second, then tap Y again before reaching MID. Watch SelectedLevel: it stays MID. Once the movement finishes, another Y press selects TOP.

The binding holds one command object. While that object is already scheduled, asking the scheduler to schedule it again does nothing. defer chooses a destination when the command starts; it does not restart an already-running command.

In the next section, we will change only the button bindings so each press creates a fresh movement command. Disable and stop the simulator before editing.
