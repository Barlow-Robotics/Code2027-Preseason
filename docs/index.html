Set up and pick a mechanism

  1. In GitHub Desktop, select Code2027-Preseason under Current Repository. If the folder is already on your computer but missing from the list, choose File → Add Local Repository and select that folder.
  2. Choose Current Branch → main. If you are getting the lesson starter from GitHub, click Fetch origin and then Pull origin if it appears.
  3. Choose Current Branch → New Branch. Enter lab/pair-name with a unique name for your pair, select main as the base if prompted, then click Create Branch. Confirm your new branch is shown under Current Branch.
  4. Open the same Code2027-Preseason folder in the team's WPILib VS Code. Open the folder that contains build.gradle. Use the project's WPILib 2027 alpha toolchain and Java 25.

Choose one track. One partner can implement the subsystem while the other checks units and runs the simulator. Swap at the telemetry step.

  • Edit src/main/java/first/robot/subsystems/Elevator.java or src/main/java/first/robot/subsystems/Arm.java. Start with the numbered TODOs.
  • Read the matching ElevatorSim.java or ArmSim.java to find the model’s limits and conversion constants. That file runs the physics and publishes the drawing.
  • Open src/main/java/first/robot/RobotContainer.java and find configureMechanisms(). The starter creates both subsystems there during desktop simulation. You’ll add bindings for your track to this method.

Run the starter once

  1. Open the Command Palette with Ctrl+Shift+P. Choose WPILib: Simulate Robot Code, select Sim GUI if prompted, and wait for robot startup. Leave the simulated robot disabled.
  2. Open the desktop AdvantageScope (WPILib) installed with the 2027 tools. Choose File → Connect to Simulator and select NetworkTables if prompted.
  3. Add a Mechanism tab. In the sidebar expand Telemetry → Preseason → Elevator or Arm and drag the Mechanism field into the tab.

Checkpoint. You can see the drawing while disabled. The elevator sits at the bottom and the unpowered arm may settle at its lower stop. Stop the run in VS Code before editing.

1. Create the goal command

In Elevator.java or Arm.java, add a target field initialized to the low preset. Replace the existing command factory at TODO 1 with the completed factory and private setter. Use runOnce to call a private setter that clamps and stores the goal in meters or degrees.

Check your elevator code 
private double targetMeters = LOW_METERS;

public Command setHeightGoalCommand(double goal) {
    return runOnce(() -> setHeightGoal(goal));
}

private void setHeightGoal(double goal) {
    targetMeters = Math.clamp(goal, ElevatorSim.MIN_METERS, ElevatorSim.MAX_METERS);
}
Check your arm code 
private double targetDegrees = LOW_DEGREES;

public Command setAngleGoalCommand(double goal) {
    return runOnce(() -> setAngleGoal(goal));
}

private void setAngleGoal(double goal) {
    targetDegrees = Math.clamp(goal, ArmSim.MIN_DEGREES, ArmSim.MAX_DEGREES);
}

The factory builds a command when RobotContainer sets up the binding. The setter runs when the scheduler starts the command. The subsystem’s runOnce makes the command require that subsystem.

2. Bind your two buttons

In RobotContainer.configureMechanisms(), keep the two subsystem variables. At TODO 2, add the operator controller and Teleop trigger. Both imports are already in that file.

var operator = new CommandXboxController(1);
var teleop = RobotModeTriggers.teleop();

Add your track’s two bindings. onTrue schedules the command when the combined trigger becomes true. Port 0 continues to drive the swerve.

Check your elevator code 
teleop.and(operator.a()).onTrue(elevator.setHeightGoalCommand(Elevator.LOW_METERS));
teleop.and(operator.y()).onTrue(elevator.setHeightGoalCommand(Elevator.HIGH_METERS));
Check your arm code 
teleop.and(operator.x()).onTrue(arm.setAngleGoalCommand(Arm.LOW_DEGREES));
teleop.and(operator.b()).onTrue(arm.setAngleGoalCommand(Arm.HIGH_DEGREES));

3. Graph the target

Add these imports below the package declaration. Create a telemetry table field next to your other fields. Replace the existing periodic() at TODO 3 so it publishes the stored target on every scheduler cycle. This uses the same WPILib API as SwerveTelemetry.java.

import org.wpilib.telemetry.Telemetry;
import org.wpilib.telemetry.TelemetryTable;
Check your elevator code 
private final TelemetryTable telemetry =
    Telemetry.getTable("Preseason").getTable("Elevator");

@Override
public void periodic() {
    telemetry.log("Target_m", targetMeters);
}
Check your arm code 
private final TelemetryTable telemetry =
    Telemetry.getTable("Preseason").getTable("Arm");

@Override
public void periodic() {
    telemetry.log("Target_deg", targetDegrees);
}

Checkpoint 1 · Press the buttons and watch the target

  1. Save and restart WPILib: Simulate Robot Code. While disabled, drag your Xbox controller from System Joysticks to port 1 in Joysticks. Check that the face-button indicators change. For keyboard input, assign a Keyboard entry to port 1 and check its mappings in the simulator’s DS menu.
  2. In AdvantageScope, connect to the simulator. Open a Line Graph tab and drag Target_m or Target_deg from Telemetry → Preseason → Elevator or Arm to the graph.
  3. Release the buttons, enable simulated Teleop, then press high and low a few seconds apart. Use Y then A for the elevator or B then X for the arm.

Expected. The target jumps from 0 to 0.65 m or 65° and back to 0. The simulation still receives zero motor voltage. If the target stays flat, check Teleop, the port 1 button indicator, and whether the command calls the setter. Stop the simulator before the next step.

4. Make the mechanism follow the goal

Add the Talon and Motion Magic request

In your subsystem, add these imports below the package declaration. Add the fields after the existing sim field. The CAN ID identifies the Talon on the bus. Keep the target field you added in checkpoint 1.

import com.ctre.phoenix6.configs.TalonFXConfiguration;
import com.ctre.phoenix6.controls.MotionMagicVoltage;
import com.ctre.phoenix6.hardware.TalonFX;
import com.ctre.phoenix6.signals.GravityTypeValue;
import com.ctre.phoenix6.sim.TalonFXSimState;
import first.robot.generated.TunerConstants;
Check your elevator code 
private final TalonFX motor = new TalonFX(20, TunerConstants.kCANBus);
private final MotionMagicVoltage positionRequest = new MotionMagicVoltage(0.0);
Check your arm code 
private final TalonFX motor = new TalonFX(21, TunerConstants.kCANBus);
private final MotionMagicVoltage positionRequest = new MotionMagicVoltage(0.0);

Apply the configuration once

Add a public constructor named after the class, before the goTo… method. Make a TalonFXConfiguration, set the feedback ratio and the Slot 0 and Motion Magic settings, then apply it. The ratio lets you talk to Phoenix in drum or arm turns. kP responds to position error, kV helps follow the profile velocity, and kG offsets gravity. The arm’s gravity compensation varies with its angle.

Check your elevator code 
public Elevator() {
    var config = new TalonFXConfiguration();
    config.Feedback.SensorToMechanismRatio = ElevatorSim.GEAR_RATIO;
    config.Slot0.kP = 5.0;
    config.Slot0.kV = 2.4;
    config.Slot0.kG = 0.28;
    config.Slot0.GravityType = GravityTypeValue.Elevator_Static;
    config.MotionMagic.MotionMagicCruiseVelocity = 2.0;
    config.MotionMagic.MotionMagicAcceleration = 6.0;

    var status = motor.getConfigurator().apply(config);
    if (!status.isOK()) {
        throw new IllegalStateException("Elevator Talon FX configuration failed: " + status);
    }
    motor.getSimState().setMotorType(TalonFXSimState.MotorType.KrakenX60);
}
Check your arm code 
public Arm() {
    var config = new TalonFXConfiguration();
    config.Feedback.SensorToMechanismRatio = ArmSim.GEAR_RATIO;
    config.Slot0.kP = 45.0;
    config.Slot0.kV = 15.0;
    config.Slot0.kG = 0.23;
    config.Slot0.GravityType = GravityTypeValue.Arm_Cosine;
    config.MotionMagic.MotionMagicCruiseVelocity = 0.45;
    config.MotionMagic.MotionMagicAcceleration = 1.5;

    var status = motor.getConfigurator().apply(config);
    if (!status.isOK()) {
        throw new IllegalStateException("Arm Talon FX configuration failed: " + status);
    }
    motor.getSimState().setMotorType(TalonFXSimState.MotorType.KrakenX60);
}

Send the saved goal to Phoenix

Keep your button bindings and command factory. Add the following lines inside the private goal setter, immediately after it clamps and stores the goal. Motion Magic takes mechanism turns.

Check your elevator code 
double goalTurns = targetMeters / ElevatorSim.METERS_PER_DRUM_TURN;
motor.setControl(positionRequest.withPosition(goalTurns));
Check your arm code 
double goalTurns = targetDegrees / 360.0;
motor.setControl(positionRequest.withPosition(goalTurns));

A 0.65 m elevator goal is about 4.14 drum turns. A 65° arm goal is about 0.181 arm turns.

Connect the simulation and log actual position

At TODO 4, replace sim.update(0.0) in simulationPeriodic(). The helper reads applied voltage, advances the physics by 20 ms, and feeds raw rotor position and velocity back to Phoenix.

sim.step(motor.getSimState());

In periodic(), leave the target log in place. Add the actual position next to it. The Talon reports mechanism turns, so multiply by the same factor you divided by when sending the goal.

Check your elevator code 
double measuredTurns = motor.getPosition().getValueAsDouble();
telemetry.log("Actual_m", measuredTurns * ElevatorSim.METERS_PER_DRUM_TURN);
Check your arm code 
double measuredTurns = motor.getPosition().getValueAsDouble();
telemetry.log("Actual_deg", measuredTurns * 360.0);

Checkpoint 2 · Compare target and actual

  1. Save and restart the simulator. Check port 1, reconnect AdvantageScope if needed, and add Actual_m or Actual_deg to the same axis as the target.
  2. Enable Teleop with the buttons released. Press the same high button, wait about three seconds, then press low. Disable when both moves are done.
  3. The target steps first, then actual position moves toward it. Check that the actual settles near the goal and that the Mechanism drawing follows it.

Done when the same buttons pass both checkpoints. Point out where the target and actual differ most and explain why.

The starter or your code fails to launch

Check that VS Code opened the folder with build.gradle and is using the WPILib 2027 toolchain. Read the first error in the terminal. A Java compile error will point to a file and line. A Talon configuration exception names the subsystem and reports the Phoenix status. Recheck the CAN ID and bus against your track.

The drawing appears but the numeric fields are missing

Check that you restarted the robot after editing and that the expected telemetry.log call is in the existing periodic() override. Check the case of Preseason, the track name, and the two keys.

The target stays flat when I press high

Verify Teleop is enabled and the button indicator lights up under port 1. Check the track’s high button and put a breakpoint inside the runOnce body. If the breakpoint never hits, inspect the trigger in configureMechanisms(). If it hits, check where you assign and log the target.

The target moves but actual stays flat or moves the wrong distance

Check that simulationPeriodic() calls sim.step(motor.getSimState()) and that SensorToMechanismRatio matches the sim. Compare the request against the expected drum or arm turns. A correct drawing with a wrong graph scale points to the conversion in periodic().

AdvantageScope shows no data

Use desktop AdvantageScope 2027 on the same computer as the simulator. Select ordinary NetworkTables in the simulator connection menu. Look for Telemetry → Swerve first. If that table is absent too, check that the robot is running and close any second simulator instance.
