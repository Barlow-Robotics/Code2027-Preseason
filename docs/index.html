Find the files in src/main/java/first/robot/subsystems. The starter already runs the physics and publishes the drawings. In desktop AdvantageScope 2027, choose File → Connect to Simulator and select NetworkTables if prompted. Open a Mechanism tab and drag in Telemetry/Preseason/<mechanism>/Mechanism. With the motor work ahead of you, gravity can settle the arm against its lower stop.

1. Configure the Talon FX

  1. Declare a TalonFX on TunerConstants.kCANBus and one reusable MotionMagicVoltage request. Use CAN ID 20 for the elevator and 21 for the arm.
  2. In a constructor, build and apply a TalonFXConfiguration. Set Feedback.SensorToMechanismRatio to the provided GEAR_RATIO. Use the starting gains below. Check the returned status with isOK() so a failed configuration is visible. Set the motor’s sim type to TalonFXSimState.MotorType.KrakenX60.
  3. Inside the existing runOnce, clamp the goal to the sim’s min and max, save that goal for logging, then pass it to positionRequest.withPosition(...) in mechanism turns. Send the request with motor.setControl(...).
  4. In simulationPeriodic(), call sim.step(motor.getSimState()) in place of sim.update(0.0). The helper feeds applied voltage into the model and gives Phoenix back rotor position and velocity.
Starting gains for the simulator

In config.Slot0, try these values for kP, kV, kG, and GravityType. In config.MotionMagic, set MotionMagicCruiseVelocity in turns/s and MotionMagicAcceleration in turns/s².

  • Elevator · 5.0, 2.4, 0.28, Elevator_Static · 2.0 turns/s, 6.0 turns/s²
  • Arm · 45.0, 15.0, 0.23, Arm_Cosine · 0.45 turns/s, 1.5 turns/s²

Units check. Divide elevator meters by ElevatorSim.METERS_PER_DRUM_TURN. Divide arm degrees by 360. Phoenix applies the gear ratio when it reports mechanism turns.

2. Log the target and actual position

Use org.wpilib.telemetry.Telemetry, the same WPILib API used for swerve. Keep the table in a field so both values go to the same place every loop.

Telemetry.getTable("Preseason").getTable("Elevator")

Use "Arm" for the arm. In periodic(), log your saved goal and read the Talon FX’s position with motor.getPosition().getValueAsDouble(). Convert the reading back to meters or degrees by multiplying by the same factor you divided by when sending the goal. Publish the two values with telemetry.log(key, value) using your mechanism’s graph fields above.

3. Bind two controller buttons

In RobotContainer.configurePreseasonMechanisms(), create a CommandXboxController(1). Port 0 is the driver. Combine your button with RobotModeTriggers.teleop() using .and(...), then call .onTrue(...) with your subsystem’s goToMeters(...) or goToDegrees(...) command. Use the supplied LOW_* and HIGH_* constants.

Use onTrue because a press selects a new goal once. The Talon FX keeps running its onboard position loop between presses.

Test the response

  1. Restart the simulator. Assign an Xbox controller to joystick port 1. If you are using an emulated controller, check its button mapping in the sim UI. Release the buttons before enabling Teleop.
  2. In AdvantageScope, open a Line Graph tab. Drag both values from Telemetry/Preseason/<mechanism> onto the same axis so they share a scale.
  3. Press high, wait for the motion to settle, then press low. The target should jump on each press, the actual should travel toward it, and the Mechanism drawing should move with it.
The target stays flat

Check that the simulator is enabled in Teleop, the operator is on port 1, and you pressed the matching button. Put a breakpoint inside the runOnce body to see whether the binding fired.

The target moves but actual stays flat

Check the Talon configuration status and confirm simulationPeriodic() calls sim.step(...). Recheck the conversion to mechanism turns and the feedback ratio.

AdvantageScope shows no data

Use desktop AdvantageScope 2027 alpha with ordinary NetworkTables. Connect to the simulator on the same computer. First look for Telemetry and the existing Swerve table to confirm the connection.
