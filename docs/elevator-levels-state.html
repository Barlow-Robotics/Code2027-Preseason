Levels

Y will increase the selected level; A will decrease it. At either end, another press stays at that end. Selection describes where we asked to go, not where we are now.

BOTTOM (0 m) → MID (0.35 m) → TOP (0.65 m)

1. Name three destinations

Open src/main/java/first/robot/Constants.java. Find this code:

Before — red marks the code being changed

        public static final double LOW_METERS = 0.0;
        public static final double HIGH_METERS = 0.65;

In Constants.java, replace the two elevator presets with three heights and two arrival tolerances. Leave ArmConstants alone. We will consider the elevator arrived when it is within 1 cm of the destination and moving slower than 2 cm per second. A position check alone could finish while the mechanism is passing through the destination.

After — green marks the added code

        public static final double BOTTOM_METERS = 0.0;
        public static final double MID_METERS = 0.35;
        public static final double TOP_METERS = 0.65;
        public static final double POSITION_TOLERANCE_METERS = 0.01;
        public static final double VELOCITY_TOLERANCE_METERS_PER_SECOND = 0.02;

2. Describe the levels with an enum

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

public final class Elevator extends SubsystemBase {
    private final ElevatorSim sim = new ElevatorSim();

In Elevator.java, insert this enum immediately inside the class, above the sim field. An enum gives us a fixed set of named values. Each value carries its height. increase() and decrease() return a value; they do not change the elevator. The switch spells out each transition. Increasing TOP stays at TOP, and decreasing BOTTOM stays at BOTTOM.

After — green marks the added code

public final class Elevator extends SubsystemBase {
    public enum Level {
        BOTTOM(ElevatorConstants.BOTTOM_METERS),
        MID(ElevatorConstants.MID_METERS),
        TOP(ElevatorConstants.TOP_METERS);

        private final double heightMeters;

        Level(double heightMeters) {
            this.heightMeters = heightMeters;
        }

        public Level increase() {
            return switch (this) {
                case BOTTOM -> MID;
                case MID, TOP -> TOP;
            };
        }

        public Level decrease() {
            return switch (this) {
                case TOP -> MID;
                case MID, BOTTOM -> BOTTOM;
            };
        }
    }

    private final ElevatorSim sim = new ElevatorSim();

3. Remember the selection

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

    private double targetMeters = ElevatorConstants.LOW_METERS;

Replace the target field with these two fields. selectedLevel starts at BOTTOM because our simulation starts there. It records the last level requested by a running movement command, not the measured position. targetMeters is the current controller target, including a hold position after interruption. Neither field is proof that we have arrived.

After — green marks the added code

    private Level selectedLevel = Level.BOTTOM;
    private double targetMeters = ElevatorConstants.BOTTOM_METERS;
