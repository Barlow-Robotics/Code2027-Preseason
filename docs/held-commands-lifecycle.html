Command lifetime

We will slow the movement, add cleanup inside the elevator, and then connect the buttons. Finish these edits before running the simulation.

1. Choose a slower movement

Open src/main/java/first/robot/Constants.java. Find this code:

Before — red marks the code being changed

        public static final double HIGH_METERS = 0.65;

Open Constants.java and find HIGH_METERS inside ElevatorConstants. Add these two constants below it. Use elevator units: a cruise speed of 0.10 meters per second (10 cm/s) and an acceleration of 0.25 meters per second squared. These describe how fast the elevator travels and how quickly its speed changes. These limits apply to the Motion Magic profile; they are not hard physical speed limits.

After — green marks the added code

        public static final double HIGH_METERS = 0.65;

        // Motion profile limits in elevator units.
        public static final double CRUISE_METERS_PER_SECOND = 0.10;
        public static final double ACCELERATION_METERS_PER_SECOND_SQUARED = 0.25;

2. Use the limits

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

        config.MotionMagic.MotionMagicCruiseVelocity = 2.0;
        config.MotionMagic.MotionMagicAcceleration = 6.0;

Open Elevator.java. Replace the two profile settings with these conversions. Divide meters per second by meters per drum turn to get drum turns per second. The same division converts acceleration to drum turns per second squared. SensorToMechanismRatio already accounts for the gears, so do not multiply by GEAR_RATIO again. Keeping our constants in elevator units makes the intended motion easier to understand. The lower speed gives us time to release the button before arrival.

After — green marks the added code

        config.MotionMagic.MotionMagicCruiseVelocity = ElevatorConstants.CRUISE_METERS_PER_SECOND
            / ElevatorConstants.METERS_PER_DRUM_TURN;
        config.MotionMagic.MotionMagicAcceleration = ElevatorConstants.ACCELERATION_METERS_PER_SECOND_SQUARED
            / ElevatorConstants.METERS_PER_DRUM_TURN;

6. Add the private command class

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

    public Command setHeightGoalCommand(double goal) {
        return runOnce(() -> setHeightGoal(goal));
    }

Find the public command factory. Keep it for now and add this private class immediately below it. goal remembers the destination. addRequirements(Elevator.this) declares ownership of the surrounding elevator object, so another elevator command interrupts this one. initialize runs when the command is scheduled. isFinished returns false, so the command remains scheduled even after arrival. end runs on interruption and performs cleanup. No execute method is needed: the Talon continues its requested control between robot loops. This class is part of the elevator internals; its motor helpers remain private.

After — green marks the added code

    public Command setHeightGoalCommand(double goal) {
        return runOnce(() -> setHeightGoal(goal));
    }

    private final class MoveToHeightCommand extends Command {
        private final double goal;

        private MoveToHeightCommand(double goal) {
            this.goal = goal;
            addRequirements(Elevator.this);
        }

        @Override
        public void initialize() {
            movementActive = true;
            setHeightGoal(goal);
        }

        @Override
        public boolean isFinished() {
            return false;
        }

        @Override
        public void end(boolean interrupted) {
            stopAndHold();
            movementActive = false;
        }
    }

7. Use the new command in the factory

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

    public Command setHeightGoalCommand(double goal) {
        return runOnce(() -> setHeightGoal(goal));
    }

Now change the public factory to construct our command. Creating a command does not schedule it or move the motor. The button binding will schedule it later. The same factory is used for both destinations; we do not need separate command classes for each button.

After — green marks the added code

    public Command setHeightGoalCommand(double goal) {
        return new MoveToHeightCommand(goal);
    }

9. Move while the button is held

Open src/main/java/first/robot/RobotContainer.java. Find this code:

Before — red marks the code being changed

        operator.a().onTrue(elevator.setHeightGoalCommand(ElevatorConstants.LOW_METERS));
        operator.y().onTrue(elevator.setHeightGoalCommand(ElevatorConstants.HIGH_METERS));

In RobotContainer.java, find configureElevatorBindings. Change only these two bindings to whileTrue. Pressing starts the command; releasing cancels it and runs end. If a second elevator command interrupts the first, the first button must be released and pressed again to restart it. whileTrue does not automatically restart an interrupted command while the button remains held.

After — green marks the added code

        operator.a().whileTrue(elevator.setHeightGoalCommand(ElevatorConstants.LOW_METERS));
        operator.y().whileTrue(elevator.setHeightGoalCommand(ElevatorConstants.HIGH_METERS));
