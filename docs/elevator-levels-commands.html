Commands

4. Create commands from the selection

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

    public Command setHeightGoalCommand(double goal) {
        return new MoveToHeightCommand(goal);
    }

Replace the old factory with these three methods. There is still only one movement command implementation. goToLevelCommand constructs it; the other two methods are convenience factories. defer waits until the command is scheduled before evaluating selectedLevel. The arrow means “run this expression later.” Without that delay, constructing the button binding would choose its destination once at robot startup. The subsystem defer helper also declares the elevator requirement. These factories do not themselves change the selection or move the motor.

After — green marks the added code

    public Command goToLevelCommand(Level level) {
        return new MoveToLevelCommand(level);
    }

    public Command increaseLevelCommand() {
        return defer(() -> goToLevelCommand(selectedLevel.increase()));
    }

    public Command decreaseLevelCommand() {
        return defer(() -> goToLevelCommand(selectedLevel.decrease()));
    }

5. Start a move to a level

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

    private final class MoveToHeightCommand extends Command {
        private final double goal;

        private MoveToHeightCommand(double goal) {
            this.goal = goal;
            addRequirements(Elevator.this);
        }

        @Override
        public void initialize() {
            movementActive = true;
            setHeightGoal(goal);
        }

Rename the private command and let it remember a Level instead of a raw height. initialize updates the selection and starts movement together. Replacing an elevator command runs its cleanup before starting the new one. We will first bind these movement commands directly to the buttons, then try repeated presses in the simulator.

After — green marks the added code

    private final class MoveToLevelCommand extends Command {
        private final Level level;

        private MoveToLevelCommand(Level level) {
            this.level = level;
            addRequirements(Elevator.this);
        }

        @Override
        public void initialize() {
            selectedLevel = level;
            movementActive = true;
            setHeightGoal(level.heightMeters);
        }

6. Finish when we arrive

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

        @Override
        public boolean isFinished() {
            return false;
        }

Replace isFinished inside MoveToLevelCommand. Math.abs measures the size of the error regardless of its direction; && requires both tests to pass. Keep end and stopAndHold exactly as they are. Cleanup now runs after normal completion too. It changes Target_m to the measured hold position, which can differ slightly from the selected level height. A canceled move does not silently resume later.

After — green marks the added code

        @Override
        public boolean isFinished() {
            double heightMeters = motor.getPosition().getValueAsDouble()
                * ElevatorConstants.METERS_PER_DRUM_TURN;
            double velocityMetersPerSecond = motor.getVelocity().getValueAsDouble()
                * ElevatorConstants.METERS_PER_DRUM_TURN;
            return Math.abs(heightMeters - level.heightMeters)
                    < ElevatorConstants.POSITION_TOLERANCE_METERS
                && Math.abs(velocityMetersPerSecond)
                    < ElevatorConstants.VELOCITY_TOLERANCE_METERS_PER_SECOND;
        }

7. Show selection separately from position

Open src/main/java/first/robot/subsystems/Elevator.java. Find this code:

Before — red marks the code being changed

        telemetry.log("MovementActive", movementActive);

Add these lines in periodic. SelectedLevel is the name BOTTOM, MID, or TOP; SelectedHeight_m is its destination height. Target_m is the motor target, and Actual_m is measured height. After interruption, SelectedLevel still records the requested destination while Target_m records the hold position. MovementActive tells us whether a movement command is running.

After — green marks the added code

        telemetry.log("MovementActive", movementActive);
        telemetry.log("SelectedLevel", selectedLevel.name());
        telemetry.log("SelectedHeight_m", selectedLevel.heightMeters);

8. Advance one level per press

Open src/main/java/first/robot/RobotContainer.java. Find this code:

Before — red marks the code being changed

        operator.a().whileTrue(elevator.setHeightGoalCommand(ElevatorConstants.LOW_METERS));
        operator.y().whileTrue(elevator.setHeightGoalCommand(ElevatorConstants.HIGH_METERS));

In configureElevatorBindings, replace the held-button bindings with these onTrue bindings. Tap Y to increase or A to decrease. Releasing the button now leaves the movement command running; reaching the destination ends it. This differs from our first walkthrough: a command owns the elevator for the entire trip. Pressing the other button replaces it and runs cleanup. Hold a button down to confirm that it advances only once.

After — green marks the added code

        operator.a().onTrue(elevator.decreaseLevelCommand());
        operator.y().onTrue(elevator.increaseLevelCommand());
